# 著名古谱讲解：橘中秘·弃马十三着

本阶段交付一份可完整播放的著名棋谱讲解：标准开局至第十三回合红方将死，25 个主线半回合，三处重点讲解，四段推演，晓晓中文语音和段落字幕。当前音频共 69 段，约 5 分 46 秒；所有棋步和分支恢复局面经过规则验证。

## 打开演示

```powershell
uv sync --locked
uv run chessmuse serve
```

打开 <http://127.0.0.1:8000>，默认载入「橘中秘 · 弃马十三着」，点击「播放解说」。可以暂停、重播、跳转关键节点，以及从任一推演分支回到对应主线局面。本工作区已生成 `audio/qima-13/`，已有有效缓存时不需要在线 LLM 或 TTS。

新工作区没有音频时，先运行：

```powershell
uv run chessmuse prepare-example --example qima-13
```

代码随附讲解脚本和已校验的走子短句，首次只需联网生成语音。音频及清单位于根目录 `audio/`，依项目规则不提交 Git；文稿与走法交付在 `src/chessmuse/data/famous-*.json`。

## 固定棋谱来源

采用[弃马十三着条目固定修订版 49799855](https://zh.wikipedia.org/w/index.php?title=弃马十三着&oldid=49799855)列出的完整十三回合次序，仅转录古谱走法，自行编写讲解。它是公共领域古谱《橘中秘》的演示，**不是现代棋手比赛记录**。原书影印资料见[橘中秘象棋谱馆藏扫描目录](https://commons.wikimedia.org/wiki/File:NLC416-14jh003409-68136_橘中秘象棋譜.pdf)。

核对时发现另一网页使用不同出子次序且只记录 11 回合，未将不同版本拼接。固定主线在 `famous-game.json`，完整校验结果：最后一手 `b7e7` 炮八平五将军，黑方没有合法走法。

## 三处讲解及证据

| 节点 | 讲解内容 | 真实运行结果 |
| --- | --- | --- |
| 第6回合黑方吃马（ply 12） | 眼前物质收益与先补防的差别 | 两种模型在1/3/5层均首选 `b7b0`；Pikafish depth16 更偏好补士，吃马约 -71 cp（黑方视角）。不宣称吃马已必败 |
| 第7回合红方进炮（ply 13） | 回车追炮与主动进炮的取舍 | 纯子力 depth5 首选 `a1a0`，把 `b2b7` 排第4；传统评价 depth5 和 Pikafish depth16 首选 `b2b7`。进炮后红炮以黑中炮为炮架，隔子攻击黑马；只证明攻击关系，不当作黑方不能应对 |
| 第10回合红方弃车（ply 19） | 先吃士将军，接受/拒绝弃车两条分支 | depth12/16 均支持 `d8d9`；接受分支送车600模型单位、至终局净损失195，仍核验到将死；拒绝分支 `f9f8` 保留为可继续计算的防守 |

另单独讲解第7回合黑方退马（ply14）：相对同一局面的专家首选，depth16 的估计损失为 778 cp。它说明不能仅凭古谱结尾就倒推“吃马必败”。分差均为当前深度的估计，未校准为跨局面通用失误阈值。

推演依次展示：黑方先补防、红方回车追炮、黑方拒绝弃车，以及古谱接受弃车直至将死。每次恢复到分支开始前记录的当前主线快照，最后继续播放至完整古谱终点。

可提交的[实验摘要](experiments/qima-13.json)记录模型排名、候选 PV、专家请求、最终原始 info、炮架证据和物质账本。完整双向 UCI 与18组模型实验保存在 `.cache/review/qima-13/evidence.json`、`.cache/analysis/`、`.cache/elephanteye/searches/`。

## ElephantEye 选型与实现

定向阅读[官方 README](https://github.com/xqbase/eleeye/blob/a3e6890386aa87ca4a184c4df8f9f13004b71565/README.md)、`position.h`、`preeval.cpp`、`evaluate.cpp` 及原搜索代码后，本机 g++ 已成功编译官方引擎。无需启用后备模型。

当前复用固定版本 `a3e6890386aa87ca4a184c4df8f9f13004b71565` 的合法走法生成、MakeMove/UndoMakeMove 和传统评价。我们另写很小的 C++ 有限深度搜索入口，以便同一深度得到**所有根候选的完整排名**，而不是将迭代加深各深度的首选误认为候选排名。

- `material`：纯子力，车600、炮285、马270、仕相120、兵卒30；不使用位置表。数值仅为模型单位。
- `traditional`：ElephantEye 传统手工评价，含阶段位置表、将帅形状、牵制、车灵活性和马受阻。
- 两者均实验1/3/5 ply，固定深度 alpha-beta，无静态搜索延伸、将军延伸、随机性和开局库。每个根候选单独用完整窗口搜索，保留准确的同深度排名；平分按 ICCS 排序。
- 每组结果保留全部候选、分数、PV、根走法吃子/将军特征、节点数和构建元数据。Python 再逐手核验 PV，所有不同的直觉首选均单独送 Pikafish 搜索。
- 这是人为设计的有限理性模型，不代表已经拟合人类棋手。固定浅层搜索会有明显水平线效应，棋力等级不能由 ply 直接推出。

构建与完整重做：

```powershell
# 需要g++。只提取固定版本中必要的C++文件及许可证
uv run chessmuse prepare-intuition --download

# 需要已准备好的Pikafish及其NNUE；使用现有.env配置
uv run chessmuse prepare-famous

# 强制重做专家证据、直觉实验、LLM计划与全部语音
uv run chessmuse prepare-famous --force
```

首次研究时整仓解压带入了旧联赛直播 PHP 上传模块并触发杀毒告警；该文件未执行。现已删除原整仓研究目录，改为白名单提取13个必要文件，禁止使用 `extractall`，不写入任何 PHP、网站或联赛模块。上游 C++ 未改动，搜索入口保存在 `scripts/intuition.cpp`。源码为 LGPL-2.1-or-later，缓存中保留其许可证；Pikafish 发布版权重仍需单独遵守其许可。

## 讲解生成的约束

程序根据真实结果形成“直觉、分歧、变化、总结”四类事实卡，关键战术断言来自规则、搜索或物质账本。LLM 仅在封闭事实卡和过渡短语中组织三处节点的段落计划；计划必须引用全部四类事实，不能添加自由战术文本，格式不合格最多要求纠正一次。

这是一种受约束的事实卡编排，**当前不是让 LLM 自由撰写长解说**。走子短句仍使用既有的上下文 LLM，并通过行棋方、行动棋子、将军、吃子和方向校验。缓存记录计划、事实卡、模型和用量。LLM 不提供前端棋步，所有主线和分支在编译时再次校验。

弃子判断当前只针对本案例的已审查候选，要求确实损失己方物质、未在展示线中完全收回、双深度专家认可，以及合法变化走到将死。仅将其称为弃子攻杀候选；没有终局证据或专家不认可的反例不归类。它不是覆盖任意棋谱的妙手分类器，也不据“连续将军”或“合法应法少”单独判断主动权。

## 验收与剩余边界

已完成真实搜索、18组直觉模型实验、完整主线终局校验、全部分支恢复校验、真实 LLM 与晓晓音频生成。真实 HTTP 导入任务完成，逐个访问69个音频文件成功；真实 Player 逻辑完整推进77个事件至第25半回合，最后可重置为初始局面。

最终代码验证通过97项Python测试（含本机真实引擎和直觉模型）及15项前端测试。源码白名单提取、炮架移除反例、未经专家认可的弃子反例、解说自由文本拒绝、多分支恢复和整段时间线均有针对性检查。

桌面工具找到浏览器后，因不能可靠识别当前网址而停止操作，本次遵守限制未继续自动控制。因此浏览器画面、实际扬声器听音及人的主观讲解质量验收仍未完成，不能用上述程序检查替代。这是目前最重要的人工体验验收项。

当前范围是**一份经审查的著名古谱**：三个关键节点由开发时指定，后续应推广节点筛选、增加实战高手名局和弃子争先样本，再扩展到任意导入棋谱的完整讲解。页面导入其他棋谱仍只生成走子短句。
