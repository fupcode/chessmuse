# 通用棋谱复盘

## 主示例

2025年5月11日五羊杯慢棋决赛，曹岩磊执红胜王禹博，共81个半回合。原始输入随源码保存在 `src/chessmuse/data/modern-game.json`，网页默认示例和下载内容使用同一局。棋谱来源及选材依据见 [候选记录](candidates/cao-wang-2025.md)。

主线与讲解分开保存。主示例使用与普通导入相同的 `review_evidence.py` 和 `autoreview.py`，没有按本局步号指定重点、写死变化或手写解说。

## 生成过程

1. 全部走法先通过棋规校验；全局低成本扫描，候选关键位置再深入复查。
2. 结合实际走法的损失、弃子、优势消失等信号选少量节点。没有足够重要的节点时允许直接概括，不为凑数量编造失误。普通等价交换排除在弃子信号之外，相邻弃子与对手应对合成一个故事。
3. 核验每条推演的合法走法、吃子、将军与终点局势；提供实战近期上下文和合法回吃关系。
4. LLM 逐节点组织讲解：实战问题、另一种选择、推演后的具体原因、回到实战的衔接。另一次模型调用对照证据审阅；失败时返回具体问题修订，最多四版。事实或格式仍不过关就保留草稿并报错。
5. 每段讲具体棋子时选择当前棋盘允许的标注，程序核对棋种和阵营。落点区域同时用于约束过河、河沿和底线的描述。编译器再次核验标注局面、主线与推演，随后准备语音。

局势判断由推演终点独立分析转换成红黑占优等短句，不让模型自行编造分值。推演结束后还需说明一个具体原因。搜索数据不进入口播。

## 开局概括

`openings.py` 按完整走法前缀匹配小型开局库，支持中炮对屏风马、顺手炮、双方起马，以及本局仙人指路转中炮对卒底炮飞象。匹配不到时继续逐步报步，避免凭前一两步猜整个布局。

匹配的2至8步共用一句概括和一段语音，保留全部中间快照与后续报步上下文。音频真正开始时才走棋，暂停和缓冲会同时暂停组内推进，跳转清除尚未执行的动画。开局概括覆盖范围内不再制造关键节点。

## 重新生成和检查

```powershell
uv run chessmuse prepare-review
uv run chessmuse prepare-review --rewrite
uv run chessmuse prepare-review --input docs/candidates/cao-wang-2025.json
```

`--rewrite` 重新生成详细讲解，仍复用适用的搜索证据和语音。成功准备主要示例后，命令会发布 `modern-review.json` 与 `modern-narration.json`，新工作区可直接复用文本。

`.cache/games/<id>/review/` 保存 `evidence.json`、`facts.json`、各节点逐版草稿、`generation.json` 和通过编译的 `review.json`。更改证据结构或讲解协议时递增对应版本；缓存按原始输入、版本和引擎身份比较，不计算文件哈希。

## 边界

当前接受标准初始局面的 ICCS JSON，最多200个半回合。识别到的开局种类仍有限；节点筛选使用启发式，模型审阅也不能替代棋手审稿。缺乏证据的复杂战略动机不应推断。传统直觉评价在本地已有可执行文件时保留为选材证据，口播直接讲选择及后果。

自动化可检查走法、返回位置、标注和播放控制；听感与画面仍需实际试听验收。

## 本次实际交付与复查

主示例自动选出第50、70、72半回合：黑炮吃相及红方防守、黑方退车放走先手、黑方退士后红车压上。最终有3条推演、17段棋盘标注、126段真实语音，语音总长约5分40秒。开局前4个行动共用一句布局概括，棋盘仍逐步落子。

本次多轮实际调用LLM后逐段检查了全文，回传具体问题再修订。重点修正了交换后仍有不存在棋子、把代表变化称为只能如此、把攻击当净赚、把实战后续和假设混淆、讲车却圈炮、底线出车误说过河等问题。最后还删去了谈不上净赚这种前文未提出观点的反驳口吻。主示例的编辑记录和逐版草稿保存在工作区的 `.cache/games/cao-wang-2025/review/`；不进入正常网页操作。
