# 第一阶段：播放闭环

播放器支持内置棋谱讲解、推演分支、导入棋谱与 LLM 走子短句。默认示例为《橘中秘·弃马十三着》，详细讲解按注意力重点拆分为短语音片段，同步展示棋子光圈或攻击关系线。

## 播放协议 v2

默认示例脚本位于 `src/chessmuse/data/famous-review.json`，内置示例目录及导入棋谱的构造、校验由 `library.py` 管理。旧 `demo.json` 保留为测试夹具。`compile_demo()` 逐步验证并编译播放数据。网页通过 `POST /api/import` 创建准备任务，再轮询 `GET /api/jobs/<任务ID>`；任务完成后使用响应中的 `result` 挂载播放器。接口与导入格式见 [棋谱导入说明](importing.md)。常规服务的旧 `/api/demo` 返回 409，不再是网页加载入口。

| 事件 | 源字段 | 执行含义 |
| --- | --- | --- |
| `move` | `move`：ICCS，如 `h2e2` | 验证走法，关联自然短句字幕与音频；音频开始时同时走子，等短句结束再推进 |
| `set_position` | `mainline_ply`，可选 `branch` | 用 650ms 过渡恢复已验证的主线快照；有分支名时进入推演 |
| `speak` | `paragraph`，可选 `chapter` | 播放对应缓存音频并显示当前段落；音频完成后推进 |

所有事件都有唯一 `id`。编译器给每个事件附加完整 `state`，包含 `fen`、`ply`、`branch`、`caption`、`last_move` 及带稳定身份的 `pieces`。走子事件另有 `before_state`、`paragraph`、`gives_check` 和 `animation_ms`。每步短句由 LLM 根据行棋方、合法中文棋谱、已核验事实和近期上下文压缩生成，保留行棋方且不含逗号等标点。结果提前缓存，播放不依赖在线 LLM；音频生成命令使用编译后的完整段落列表。ICCS 的 a0 在红方左下角，FEN 从黑方底线开始。前端只渲染通过校验的快照，主线上的每一步必须与独立棋谱吻合，时间线最后必须回到主线终点。

`Player` 统一持有音频对象、定时器和动画控制器。走子与报步属于同一个事件：声音实际开始播放后才启动动画，动画时长为 `min(550ms, 报步时长 × 60%)`，因此先完成落子，再听完报步。有详细解释时，在该 `move` 后安排 `speak`；没有则直接安排下一个 `move`。`set_position` 通过可暂停的 650ms 动画过渡，完成后推进下一条语音：存活棋子滑回，被吃棋子淡入，额外棋子淡出。语音关闭时仍按对应音频时长保留字幕。

暂停同时保留音频位置、动画进度或剩余定时；音频缓冲时也暂停动画，恢复发声后继续。跳转会清理旧音频、动画和定时器，停在所选走子的起始局面，点击播放后重新报步并走棋。重播从头开始；「回到主线」从当前可见分支局面启动恢复动画；原先播放中则继续讲解，原先暂停则完成恢复后保持暂停。切换声音开关会重新开始当前事件。减少动态效果模式下直接落子。动画使用可暂停、继续和取消的 Web Animations API。

进度滑块按事件编号定位，不是秒级时间轴，也不支持拖到一句语音的中间。音频出错会暂停；再次播放时从当前事件开头重试。导入准备失败保留原播放器，不把失败标成完成；服务重启后任务进度丢失，需要重新选择棋谱。

## 验证记录与边界

截至 2026-10-20，已在本机完成合法主线与分支校验、真实音频生成和时长读取、HTTP 页面/导入任务/音频访问，以及缓存复用检查。最近通过 78 项 Python 测试和 13 项前端测试。自动化测试使用模拟 LLM 和微型音频，与真实服务检查分别进行。

根目录 `audio/<棋谱ID>/audio.json` 保存显示原文 `text`、合成文本 `spoken_text`、声音、语速和文件名，并检查文件可读且时长为正，不计算文件哈希。象棋「车／車／俥」仅在合成文本中替换为「居」，读 jū（一声），字幕和 LLM 原文不变；发音规则失配时重新生成受影响片段。

默认缓存为晓晓神经网络女声（`zh-CN-XiaoxiaoNeural`，语速 `+8%`，即 108%）的 MP3，通过 edge-tts 联网生成，缓存齐全后播放无需联网。编译器也支持 Windows 慧慧 WAV。所有段落生成并校验成功后才更新当前清单，失败保留旧清单。重新合成的片段使用独立文件名，匹配的旧片段保留文件名并复用。旧文件暂不自动删除，服务只开放当前清单中的音频。音频与清单不纳入 Git。

网页始终以默认晓晓、108% 准备棋谱，会替换与此配置不匹配的缓存；命令行试用其他声音或语速后，重新选择示例不会保留该自定义配置。开发时 `prepare-example --force` 重做短句和全部音频，`prepare-audio --force` 只重做音频；后者要求已有有效短句。详见 [README](../README.md)。


## 注意力标注

`review.py` 把已审阅事实卡按短句拆为 units。LLM 返回每段的 unit 引用及一个 focus 引用（或 null），不输出坐标。提示词要求一段一个注意力重点，过渡句不强行加标注；编译时拒绝片段遗漏、乱序和未授权 focus。当前示例共 99 段语音、107 个事件，12 个片段带标注。

`paragraph.annotation` 包含 id、label、fen、rings 和 arrows；`fact_ref` 保留该短片段的事实引用。编译器检查标注 FEN 与播放局面相同，光圈指向真实棋子，箭头符合合法走法或攻击关系。红炮、黑中炮、黑马的攻击关系额外复用已有炮架核验。原始证据不足以支持的标注不会交给播放器。

标注在对应短语音开始时出现，暂停时保留，跳转、走子或下一片段会清除或切换。攻击线绘制在棋子下方，光圈绘制在棋子上方，避免盖住棋子文字。右上角随当前局面显示“推演中”，回到主线后恢复网站说明。`set_position` 进入与离开分支时均清除旧标注。

本次已完成真实 LLM 标注编排、分段 TTS、真实 HTTP 准备及全部音频访问检查；当前工具没有可连接的浏览器，页面实际视觉与听音仍需人工体验确认。


## 推演收尾

每条分支最后一手之后，在末局面依次播放“局势结论”和“具体原因”，再执行返回动画；回到主线后点明实际采用的走法。结论不在引入段提前播报，也不在棋盘已返回后才解释已经消失的变化。

`branches.py` 统一定义展示的分支走法。准备古谱时，对这四条分支的实际终点独立复查，并验证评价记录的 FEN、完整历史和行棋方视角；不使用分支开头的评价冒充末局面的结果。内部评价转为“大致均衡”“稍占上风”“明显占优”“大优”等口语，分数不进入字幕或语音；非精确界限只给保守结论，将死与普通分值分开处理。用来选择措辞的区间是当前演示的编辑规则，未作为通用棋力或胜率标尺。

当前复查结论：补防与追炮两条变化大致均衡，拒绝弃车后红方仍然大优，接受弃车的展示线走到将死。四条末局面的原始评价与具体收尾记录在 `docs/experiments/qima-13.json` 的 `branch_reviews`。收尾语音已重新生成，其余片段复用。
