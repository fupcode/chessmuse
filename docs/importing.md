# 棋谱导入与生成

网页的示例选择和本地文件导入使用同一条后台准备流程：完整走法校验 → 全局扫描与关键选择复查 → LLM 分段复盘与独立审阅 → 检查走子短句缓存 → 检查语音缓存 → 必要时合成音频 → 读取真实时长并编译播放数据。

## 格式

仅接受 JSON 对象，`title` 为可选标题（最多100字），`moves` 为必填 ICCS 列表，例如 `h2e2`。从标准初始局面开始，红方先行，最多200个半回合。当前不支持自定义起始局面和多格式兼容。整份文件最大256KB，非法棋步会在调用模型之前被拒绝。

## HTTP 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/examples` | 可选示例的名称和标识 |
| `GET /api/examples/<id>/download` | 下载可导入的 JSON 示例 |
| `POST /api/import` | 提交 `{"example_id":"cao-wang-2025"}` 或 `{"game":{"title":"棋谱","moves":["h2e2"]}}` |
| `GET /api/jobs/<job_id>` | 查询任务阶段、进度、错误或最终播放数据 |
| `GET /audio/<game_id>/<file>` | 读取当前音频清单允许的 MP3/WAV 文件 |

创建任务返回202与 `job_id`。任务状态为 `queued`、`processing`、`complete` 或 `error`。进度来自实际校验、LLM批次及TTS片段完成数量；前端轮询并动画显示进度，不用定时器虚构百分比。完成后 `result` 包含播放器需要的合法快照与音频URL。

同一棋谱正在处理时复用进行中的任务；不同棋谱最多两个后台任务并行执行。浏览器导入失败时保留当前棋局，允许重试。后台任务目前在内存中，服务重启后需要重新选择棋谱；已写入磁盘的短句和语音缓存仍然有效。

## 文件管理

语音与音频清单只放在根目录 `audio/<game_id>/`，整个 `audio/` 被 Git 忽略。生成过程不会自动删除旧版本片段；服务只提供当前清单引用的音频，因此开发时强制生成后应在网页重新选择该棋谱。旧版本可在停服时手工清理。

`.cache/games/<game_id>/script.json` 保存本地导入棋谱，`narration.json` 保存生成短句与完整输入。相同导入通过原文数据比较查找，不计算文件哈希。主要示例 `cao-wang-2025` 可复用随源码提供的已审阅复盘和走子短句，所有语音仍由本地生成或已有文件提供。

`prepare-review --rewrite` 重新生成详细复盘并审阅；`prepare-example --force` 重新生成走子短句与音频；网页默认始终复用有效缓存。`prepare-audio --force` 只重新合成语音。命令行重新生成后，网页重新选择示例即可读取新清单。

详细复盘、逐版草稿和证据保存在 `.cache/games/<game_id>/review/`。旧版导入缓存再次导入时会迁移到完整复盘流程。精确匹配开局库的布局可由一段短句概括2到8步，棋盘仍逐步走子；未识别的开局保留正常报步。详见 [通用复盘](generic-review.md)。
